# focus-views

focus-views 是一个 Windows 原生隔离与恢复运行时研发项目，完全独立于 Focus。它研究在不依赖虚拟机的前提下，为原生图形应用提供独立交互环境、可恢复检查点和运行状态分叉能力。各分支独立执行并保留自身状态、记录和成果；调用者可以从共同检查点创建新分支，在其中开展成果整合。运行时负责隔离与恢复，不负责 Agent 决策、任务调度或自动状态合并。

**当前阶段：受限 R4 闭环与两款协作应用复用已有实测，R5-002 已验证旧 v1 三帧兼容和真实 v2 四帧执行恢复。** 支持范围仍限于同构建固定布局、编译期协作、单 GUI 线程及已知 Win32 控件/文件；通用 Windows 应用、任意调用深度和跨管理器重启恢复未验证。人工宿主交互未执行，历史 CreateProcessW/5 可靠性门禁未关闭。各轮实际结果与历史失败分别列于下文。

## 固定边界

- C++20 + Windows SDK，首先面向 Windows 11 x64。
- 使用宿主操作系统，不运行客体操作系统，不依赖虚拟机。
- 先研究用户态运行时；需要内核配合时单独论证并引入原生驱动。
- 首阶段仅管理由运行时启动的应用。
- 应用交互不抢占用户真实桌面的输入、焦点或鼠标捕获。
- 对外领域对象只有 `View`、`Snapshot`、`Action`、`Frame`、`Artifact`；任何程序都可以调用，Focus 只是潜在调用者。
- 不以截图、目录复制、冷启动或应用专用导入导出代替运行现场恢复。

## 目标流程

```text
运行中的 View ──保存──> S0（固定起点）
                         ├──派生──> A ──独立操作──> SA + 记录 + 成果
                         ├──派生──> B ──独立操作──> SB + 记录 + 成果
                         └──派生──> C（从原始现场继续）
                                      ↑
                              读取 A/B 的固定成果版本
                              或导入分支私有副本
```

调用者决定由谁操作、何时停止、采用哪些成果以及怎样整合。运行时不提供自动状态合并。

受管键盘机制见 [R3-002 运行说明](experiments/r3-002/README.md) 和 [实际报告](experiments/r3-002/results/20261024-r3002/report.md)：线程钩子在目标 GUI 线程更新真实队列键态后，同一个原生 EDIT 的 Shift+End 从无效变为真实选择。仅验证指定键盘子集，后台异步键态和完整 R3 仍未完成；原生基线与历史失败保持不变。

[R3-003](experiments/r3-003/README.md) 已实测通过指定 EXE IAT 路径上的私有异步按下高位，并验证它在输入接受时生效、独立于消息消费；这是明确的 API 虚拟化。详见 [原始记录与报告](experiments/r3-003/results/20261024-r3003/report.md)。范围仍限于单 GUI 线程及指定按键，不代表完整异步 API、键鼠隔离或 GUI 恢复。

[R3-004](experiments/r3-004/README.md) 已实际验证受管左键/虚拟光标、所属窗口命中、真实捕获的越界路由，以及 A 保持拖拽时 B 点击原生按钮；原版 fixture 的真实 GDI 图像和失败日志见 [报告](experiments/r3-004/results/20261024-r3004/report.md)。宿主静止采样与人工交互分别判定，人工未执行；这仍是冷启动 GUI 子集，完整 R3 和 GUI 恢复尚未完成。

[R3-005a](experiments/r3-005a/README.md) 已编译并实测，但 GUI 执行恢复未通过：新进程中已重建固定自绘窗口并写回声明的内存、C++ 栈和基本上下文，首个 RET 因 CET 影子栈不匹配失败。原始异常、最小复现和分层结果见 [报告](experiments/r3-005a/results/20261024-r305a/report.md)。未关闭保护，该原始失败不因后续协作机制通过而改写。

[R3-005a-CET-001](experiments/r3-005a-cet-001/README.md) 已完成官方上下文与受保护返回链对照：目标自身返回/SEH 正常，源退出后的 SetThreadContext、CET_U 原值及 RtlRestoreContext 路径均未恢复源执行链。实际矩阵、异常与 EHCONT 元数据见 [报告](experiments/r3-005a-cet-001/results/20261024-cet001/report.md)；GUI 恢复仍未通过。

[R3-005a-CET-002](experiments/r3-005a-cet-002/README.md) 已实测通过**编译期协作续接子集**：新进程在相同 CALL 位置合法建立自己的 CET 返回链，恢复原始内存、栈和计算寄存器，正常返回且不重放业务前缀；随后固定自绘窗口、已知 HWND 引用、真实 GDI 和既有输入整合通过。正反对照、原始图像及严格边界见 [报告](experiments/r3-005a-cet-002/results/20261024-cet002/report.md)。需要明确编译协作，不代表任意未改造 GUI 或完整 R3。

[R3-005b-001](experiments/r3-005b-001/README.md) 已实际验证原生 EDIT 文本、选区、修改标志、线程焦点及固定顶层/EDIT/BUTTON 关系的重建，随后从 S0 正常 CALL/RET、真实绘制并继续键盘选择和输入。18 次运行、280 项证据检查符合预期，另完成 CET-002 的 14 次全量回归。详见 [原始资源、图像及报告](experiments/r3-005b-001/results/20261025-r3005b001/report.md)。仅支持报告列明的单行 ASCII/默认控件配置；非空撤销历史、未知子窗口/引用及不一致关系拒绝，未开始 R4。

[R3-005c-001](experiments/r3-005c-001/README.md) 已实际验证同一不可变 GUI S0 恢复 A/B，交错编辑原生 EDIT 与受管内存后，在两者继续运行时恢复 C；B 原生资源重建失败时，A 可继续工作，C 仍从 S0 恢复。正式 6 次运行、670 项证据检查通过，另完成 b001 与 CET-002 全量回归。见 [原始日志、分支图像及报告](experiments/r3-005c-001/results/20261025-r3005c001/report.md)。仅覆盖既有编译协作和控件子集；修改后的分支有非空撤销历史，尚未保存可恢复 SA/SB，也没有 Artifact 导入或完整 R4。

[R4-001](experiments/r4-001/README.md) 已实测应用通过真实 BUTTON 和 Win32 文件 API 生成成果，发布固定 A-v1/B-v1 与 A-v2，C 从 S0 恢复后读取和修改私有副本。常驻桥版本本体 8 次完成、2,859 项本体检查通过，120 个显式进程实例和 32 个 Desktop 清理确认；**整套脚本因旧回归的 PID 核对及 CreateProcessW 拒绝仍为失败**，不能称全绿。来源、Action、原始文件/哈希、真实图像及所有失败见 [分层报告](experiments/r4-001/results/20261025-r4001-resident/report.md)。SA/SB 非空撤销继续拒绝，没有完成完整 R4 或通用文件系统隔离。

[GATE-002 系统诊断](experiments/r4-001-gate-002/report.md) 已按固定边界执行：本轮 3,024 次自然创建未复现拒绝；ETW 普通会话及内存/标记可用，但启用 Kernel-Process 返回访问拒绝。交付生命周期日志、44 个内存样本及 3,072 个标记，根因仍未确认，管理员独立采集未执行。原功能实现和成功回归证据不变，本轮未重跑功能回归，可靠性门禁保持未关闭。

[R4-002a](experiments/r4-002a/README.md) 已实测通过单次标准 EDIT Undo 与修改后 SA/SB 的受限恢复：原 A/B 退出后，新 PID 恢复各自原始内存、栈、R10 和原生控件撤销语义，正常 CET CALL/RET、两次 Undo 及继续输入/绘制。20 个集成场景、2 次最小原生对照、1,674 项证据检查及 c001/b001/CET-002 完整回归通过，详见 [正式报告](experiments/r4-002a/results/20261025-r4002a/report.md)。仅全选后一次 ASCII 字符替换、固定窗口树与编译协作；完整 R4 尚未验收。

[最后一次管理员 ETW 取证](experiments/r4-001-gate-002/results/20261025-admin-final/report.md) 已完成：仅 collector 提升，普通探针 64 次调试创建成功；Kernel-Process 可采集，但历史拒绝未复现、根因未确认。系统诊断停止追加次数，可靠性 gateClosed=false 与恢复机制研究分别判定。

[R4-003-001](experiments/r4-003-001/README.md) 将可恢复 SA/SB 与固定成果流整合到同一条运行链：A/B 一次真实 EDIT 编辑并经 BUTTON 生成文件，发布 A-v1/B-v1，保存包含私有工作文件版本的 SA/SB；原 A/B 退出后恢复 RA/RB，C 从原 S0 恢复并实际读取/处理两个固定成果。正式 14 次集成场景、2,519 项证据检查以及 R4-001/R4-002a 各自全量嵌套回归通过；原始执行、Undo、文件对象隔离、Action 与真实 GDI 分别核对，见 [正式报告](experiments/r4-003-001/results/20261025-r4003001/report.md)。只声明本实验资源范围内的 R4 整合，不代表通用 Windows 应用支持；创建可靠性门禁仍未关闭。

[R5-001a](experiments/r5-001a/README.md) 已将 manager、fixture 和 helper 物理拆成独立 EXE，恢复内核与业务验收客户端分开。独立管理器使用目标 PE 的只读诊断副本及目标函数表完成 unwind/CET 核对，实际重跑原 R4 链路。20 次新场景、3,710 项证据检查及旧 R4-003 全部嵌套回归通过，见 [报告](experiments/r5-001a/results/20261025-r5001a/report.md) 与研究构建包。只验证一个显式协作应用，不是任意程序兼容、稳定 SDK 或管理器重启恢复；可靠性门禁仍未关闭。

[R5-001b](experiments/r5-001b/README.md) 已用同一个新 manager 和逐字节未变的 R5-001a 内核管理两款业务不同的协作应用。独立数据记录器使用采样数组、另一套计算及 CSV；两款应用均完成既有受限 R4 链路。最终 42 次场景、8,028 项证据检查及旧 R5-001a/R4-003 完整嵌套回归通过，见 [最终报告与构建包](experiments/r5-001b/results/20261025-r5001b-neutral/report.md)。首轮输入会话初始键态失败单独保留；共享客户端增加已确认的 key-up/release 握手，内核和输入组件不改。仍不支持任意应用、动态执行 ABI、长期快照或管理器重启恢复，可靠性门禁未关闭。

[R5-002](experiments/r5-002/README.md) 已实测通过有限可变深度协作恢复：同一新版内核兼容两款未重编译的 v1 三帧应用，并恢复真实 v2 四帧调用链，继续完成既有受限 R4。70 个主场景、3 个安全点对照、14,154 项本轮证据核验与旧 R5-001b/R5-001a/R4-003 完整嵌套回归通过，见 [正式报告与运行包](experiments/r5-002/results/20261026-r5002-verified/report.md)。前两轮失败保留；仅三/四帧、同构建固定布局及已知 GUI/文件资源，不是任意深度、未改造应用或跨 manager 重启恢复，历史创建可靠性门禁仍未关闭。
