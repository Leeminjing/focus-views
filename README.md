# focus-views

最新跟进：[PID 实例身份修复](experiments/r5-003/results/pid-identity/report.md) 已通过确定性对照及 R5-003 本体；完整旧回归仍因更深层输入钩子 /126 失败。[文本服务裁剪实验](experiments/r5-004c-wait/results/wait001/report.md) 已在不读取 Snapshot/Session 的管理器中复现正常关闭与停止点关闭的同类等待，WCT 实际追到 COM 对象及 RPCSS 的 PID 终点；具体服务端操作仍未知，没有清理修复或 R5-004 全关口通过声明。

focus-views 是一个 Windows 原生隔离与恢复运行时研发项目，完全独立于 Focus。它研究在不依赖虚拟机的前提下，为原生图形应用提供独立交互环境、可恢复检查点和运行状态分叉能力。各分支独立执行并保留自身状态、记录和成果；调用者可以从共同检查点创建新分支，在其中开展成果整合。运行时负责隔离与恢复，不负责 Agent 决策、任务调度或自动状态合并。

**当前阶段：R5-003 已通过受限的正常退出跨管理器恢复；R5-004 已实跑但尚未通过异常退出关口。** 最新实验有 8 个提交后完整恢复正例和 32 个提交前拒绝，但恢复中再崩溃的后续操作遇到映像基址变化及停止点资源清理问题。仍限于同会话、同构建/匹配布局、编译期协作、单 GUI 线程和已知 Win32 资源；宿主重启、断电、稳定格式与通用应用未验证。人工宿主交互未执行，历史 CreateProcessW/5 门禁独立保留。

## 固定边界

- C++20 + Windows SDK，首先面向 Windows 11 x64。
- 使用宿主操作系统，不运行客体操作系统，不依赖虚拟机。
- 先研究用户态运行时；需要内核配合时单独论证并引入原生驱动。
- 首阶段仅管理由运行时启动的应用。
- 应用交互不抢占用户真实桌面的输入、焦点或鼠标捕获。
- 对外领域对象只有 `View`、`Snapshot`、`Action`、`Frame`、`Artifact`；任何程序都可以调用，Focus 只是潜在调用者。
- 不以截图、目录复制、冷启动或应用专用导入导出代替运行现场恢复。

## 目标流程

```text
运行中的 View ──保存──> S0（固定起点）
                         ├──派生──> A ──独立操作──> SA + 记录 + 成果
                         ├──派生──> B ──独立操作──> SB + 记录 + 成果
                         └──派生──> C（从原始现场继续）
                                      ↑
                              读取 A/B 的固定成果版本
                              或导入分支私有副本
```

调用者决定由谁操作、何时停止、采用哪些成果以及怎样整合。运行时不提供自动状态合并。

## R5-004：异常终止诊断与未关闭的恢复门禁

R5-004 已实际执行，整体未通过。最新 63 场景/1,982 项检查中 17 项失败；8 个提交后真实强杀管理器的完整恢复正例、32 个提交前拒绝符合预期。恢复中再崩溃后的新操作因目标映像基址变化被拒绝，停止点失败分支 Desktop 清理亦未确认，后续尝试被归属门禁阻断。v/f 两次完整旧回归通过，g 未重跑未变依赖；120 个固定版本后验哈希保持。不能将已有成功扩大为可靠的管理器崩溃恢复。 详见 [实际报告](experiments/r5-004/results/r5004/report.md)。历史原生创建可靠性问题保持独立，人工交互未执行；没有宿主重启或断电恢复声明。


## R5-004a：写入源状态前的停止点失败清理

[正式报告](experiments/r5-004a/results/r5004a/report.md) 增加 CAP-19 的受限证据：在真实 checkpoint、首次源内存/栈/cookie/CPU 写入之前拒绝恢复，由目标 GUI 线程经原生异常分发进入运行时清理，DestroyWindow 后 ExitProcess。独立监督器随后确认实例、Job、自有句柄和 Desktop，不以 CloseDesktop 返回成功代替对象消失。

最终 f 矩阵 12 场景、1,538 项核验通过：6 个写入前清理及新 Manager 完整恢复链（其中 2 个验证 RB 拒绝后 RA 仍绘制），另 6 个错误线程、缺失运行时映射、写回后故障的安全反例。36 个管理器实例、86 个 Desktop 均有独立清理证明。完整旧回归已在 c 中实跑通过；f 仅重跑受影响的新矩阵，未再次运行旧全量套件。中间 b/d 的 false summary 与早期失败保留。

清理回调仅允许干净的目标引导现场；首次源状态写入前标记实例为 dirty，此后禁止目标侧分发，采用终止及严格监督。DLL/钩子是运行时资源，不修改应用 EXE。Windows 内部保留 Desktop 引用的精确原因仍未直接证明。ASLR 异基址、完整 R5-004、历史 CreateProcessW/5、宿主重启/断电和人工宿主交互均未因此通过。


## R5-004b：受限异基址续接与仍开放的清理门禁

[R5-004b 实测报告](experiments/r5-004b/results/r5004b/report.md) 已验证同 SHA256 的 EXE 在真实不同基址加载后，三/四协作帧恢复原始内存、栈、CPU 并完成目标自己的 CET CALL/RET，继续 GUI/Undo/私有文件及成果流。最终 16 场景、1,958 项主检查通过；最终构建另完成原 R5-004 的 63 场景、3,174 项检查。完整旧嵌套回归在开发轮实跑通过，未将其写成最终轮再次运行。

## R5-004c：清理候选被自然反例否定
